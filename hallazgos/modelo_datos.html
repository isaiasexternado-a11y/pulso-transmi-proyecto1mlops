01

El principio: todo cuelga de la corrida

Hay una decisión que gobierna el resto del diseño. Cada fila que el pipeline produce guarda el run_id de la ejecución que la produjo.

Suena burocrático hasta que un evaluador pregunta «¿por qué el 14 de octubre el modelo predijo esto?». Con run_id en todas partes, la respuesta es una consulta: qué commit corría, con qué cutoff, qué señales de drift vio, qué decidió, con qué modelo predijo. Sin él, la respuesta es arqueología de logs.

02

Los cuatro tiempos (aquí es donde se pierde el reto)

La confusión entre estos cuatro campos es la causa número uno de fuga de información en un pipeline de series temporales. Valen la pena nombres distintos y explícitos.

Los cuatro tiempos, y el quinto que no es un tiempo del mundo
CampoSignificaDónde vive¿Sirve como feature?
observed_atEl instante real que la fila describeobservations, contextSí — es el eje del problema
cutoff_atHasta dónde había datos cuando corrió el pipelinepipeline_runs, models.train_endNo, pero define qué es legal mirar
issued_atCuándo se emitió la predicciónpredictionsNo
target_atPara qué instante pronosticapredictionsSí — su calendario (slot, día)
ingested_atCuándo la fila entró a la basecasi todasNunca
El error clásico, en una línea

Entrenar con WHERE observed_at <= now() en vez de <= cutoff_at. Funciona perfecto en el backtest —porque la base ya tiene el futuro cargado— y falla en producción, donde ese futuro todavía no existe. cutoff_at guardado en models.train_end es lo que hace el entrenamiento reproducible seis semanas después.

Y tres vistas, que no son tablas a propósito

El scoring —comparar predicción contra realidad— es completamente derivable. Guardarlo en una tabla crea una copia que se desincroniza en cuanto llega una observación tardía o se corrige una fila. Por eso es una vista:

VistaQué resuelve
v_prediction_scoresUne predictions con observations por (station_id, target_at = observed_at). Solo aparecen las predicciones cuya verdad ya llegó.
v_accuracy_rollingAccuracy 24 h y acumulada por estación. Alimenta el dashboard y el drift de desempeño.
v_active_modelEl modelo vigente. Una sola fila, garantizada por un índice único parcial.

La relación que no es una clave foránea

predictions y observations se unen por (station_id, target_at = observed_at), pero no lleva FK: cuando se emite la predicción, esa observación todavía no existe. Es una relación diferida en el tiempo, y por eso el scoring es una vista y no una columna.

05

Qué escribe cada paso de una corrida

Los siete pasos que exige el reto, mapeados uno a uno contra la tabla que tocan.

La política de reentrenamiento, en concreto

El EDA da los umbrales. La variación normal semana a semana por estación está entre −0,3 % y +5,5 %, así que ±5 % es ruido, no señal. Una política defendible:

  1. Mide

    Por corrida y por estación: wape_24h, wape_7d, desplazamiento de nivel a 7 días, correlación del perfil de 96 slots contra el de entrenamiento, sesgo del residuo y huecos de ingesta.

  2. Dispara solo fuera de la banda de ruido

    Reentrena si el accuracy rolling de 7 días cae más de 3 puntos respecto al de validación del modelo activo, o si el desplazamiento de nivel supera el ±5 % medido, o si la correlación del perfil baja de 0,95.

  3. Respeta un enfriamiento

    cooldown_until impide reentrenar dos veces en menos de 24 h. Sin esto, un día raro provoca una cascada de reentrenamientos que empeora el modelo.

  4. Campeón contra retador

    El modelo nuevo nace candidate. Solo pasa a active si supera al vigente sobre la misma partición temporal. Si no, queda rejected y el vigente sigue. El índice único parcial garantiza que nunca haya dos activos.

  5. Ten un suelo

    El baseline de perfil por slot vive en models con accuracy 88,11 registrada en model_metrics. Si el modelo activo cae por debajo, la decisión es rollback al baseline. Es un control negativo y un plan de contingencia a la vez.

06

DDL completo

PostgreSQL 15+ (lo que corre Supabase). El orden de creación respeta las dependencias de clave foránea.

-- ============ CAPA 1 · DATOS ============

create table stations (
  station_id    text primary key,           -- text, NO integer: los ceros iniciales
  station_name  text not null,
  corridor      text not null,
  latitude      double precision not null,
  longitude     double precision not null,
  vagones       smallint,                    -- enriquecido del ArcGIS oficial
  accesos       smallint,
  tipo          smallint,                    -- 1 = portal
  is_portal     boolean generated always as (station_name like 'Portal%') stored,
  seeded_at     timestamptz not null default now()
);

-- ============ CAPA 2 · ORQUESTACIÓN (va antes: todo la referencia) ============

create table pipeline_runs (
  run_id        bigint primary key,          -- GITHUB_RUN_ID: ya es único y rastreable
  attempt       smallint not null default 1,  -- GITHUB_RUN_ATTEMPT
  trigger       text not null check (trigger in ('schedule','manual','retry')),
  git_commit    text not null,                -- GITHUB_SHA
  git_ref       text,
  run_url       text,
  started_at    timestamptz not null default now(),
  finished_at   timestamptz,
  status        text not null default 'running'
                check (status in ('running','success','failed','partial')),
  cutoff_at     timestamptz,                 -- hasta dónde había datos al empezar
  rows_ingested integer not null default 0,
  error_stage   text,
  error_message text
);

create table run_events (
  event_id  bigserial primary key,
  run_id    bigint not null references pipeline_runs on delete cascade,
  stage     text not null check (stage in
            ('ingest','features','monitor','decide','train','predict','submit')),
  level     text not null check (level in ('info','warning','error')),
  message   text not null,
  payload   jsonb,
  at        timestamptz not null default now()
);
create index on run_events (run_id, at);
create index on run_events (at desc) where level = 'error';

-- ============ CAPA 1 · DATOS (continuación) ============

create table observations (
  station_id  text not null references stations,
  observed_at timestamptz not null,
  demand      integer not null check (demand >= 0),
  run_id      bigint not null references pipeline_runs,
  ingested_at timestamptz not null default now(),
  primary key (station_id, observed_at)   -- la clave natural = idempotencia gratis
);
create index on observations (observed_at desc);

create table context (
  observed_at          timestamptz primary key,
  rain_mm              double precision,
  rain_forecast        double precision,
  temperature_c        double precision,
  temperature_forecast double precision,
  event_intensity      double precision,
  run_id               bigint not null references pipeline_runs,
  ingested_at          timestamptz not null default now()
);

-- ============ CAPA 3 · MODELO ============

create table models (
  model_id          uuid primary key default gen_random_uuid(),
  name              text not null,
  kind              text not null check (kind in ('baseline','ml')),
  algorithm         text not null,          -- 'profile_slot' | 'naive_week' | 'lightgbm'
  hyperparams       jsonb not null default '{}',
  feature_set       text not null,          -- 'fs-v3'
  feature_list      text[] not null,
  train_start       timestamptz,
  train_end         timestamptz,            -- el cutoff con el que se entrenó
  n_train_rows      integer,
  artifact_uri      text,                   -- Supabase Storage o release asset
  artifact_sha256   text,
  git_commit        text not null,
  trained_by_run_id bigint references pipeline_runs,
  parent_model_id   uuid references models,  -- linaje: a quién reemplazó
  status            text not null default 'candidate'
                    check (status in ('candidate','active','retired','rejected')),
  activated_at      timestamptz,
  retired_at        timestamptz,
  created_at        timestamptz not null default now()
);
-- invariante en la base, no en el código: como máximo UN modelo activo
create unique index one_active_model on models (status) where status = 'active';

create table model_metrics (
  model_id     uuid not null references models on delete cascade,
  split        text not null check (split in ('train','validation','backtest','production')),
  fold         smallint not null default 0,
  station_id   text references stations,     -- NULL = métrica agregada
  metric       text not null check (metric in ('wape','accuracy','mae','rmse','bias')),
  value        double precision not null,
  window_start timestamptz,
  window_end   timestamptz,
  computed_at  timestamptz not null default now(),
  unique nulls not distinct (model_id, split, fold, station_id, metric)
);

-- ============ CAPA 4 · SALIDA Y MONITOREO ============

create table predictions (
  run_id     bigint not null references pipeline_runs,
  model_id   uuid not null references models,
  station_id text not null references stations,
  issued_at  timestamptz not null,
  target_at  timestamptz not null,
  horizon    smallint not null check (horizon between 1 and 4),
  y_pred     double precision not null check (y_pred >= 0),
  submitted  boolean not null default false,
  submit_response jsonb,
  created_at timestamptz not null default now(),
  primary key (run_id, station_id, target_at),
  -- el horizonte no puede contradecir a los timestamps
  check (target_at = issued_at + (horizon * interval '15 minutes'))
);
create index on predictions (station_id, target_at);
create index on predictions (target_at desc);

create table drift_signals (
  run_id      bigint not null references pipeline_runs on delete cascade,
  station_id  text references stations,        -- NULL = señal global
  signal      text not null check (signal in
              ('wape_24h','wape_7d','level_shift_7d','profile_corr',
               'residual_bias','ingest_gap')),
  value       double precision not null,
  threshold   double precision not null,   -- se guarda el umbral vigente ese día
  breached    boolean not null,
  computed_at timestamptz not null default now(),
  unique nulls not distinct (run_id, station_id, signal)
);

create table retrain_decisions (
  run_id             bigint primary key references pipeline_runs on delete cascade,
  decision           text not null check (decision in
                     ('keep','retrain','rollback','blocked')),
  reason             text not null,           -- en prosa, para el evaluador humano
  breached_signals   text[] not null default '{}',
  incumbent_model_id uuid references models,
  new_model_id       uuid references models,
  cooldown_until     timestamptz,
  decided_at         timestamptz not null default now()
);

-- ============ VISTAS ============

create view v_prediction_scores as
select p.run_id, p.model_id, p.station_id, s.corridor,
       p.issued_at, p.target_at, p.horizon, p.y_pred,
       o.demand as y_true,
       abs(o.demand - p.y_pred) as abs_error
from predictions p
join observations o
  on o.station_id = p.station_id and o.observed_at = p.target_at
join stations s on s.station_id = p.station_id;

create view v_accuracy_rolling as
select station_id, model_id,
       100 * greatest(0, 1 - sum(abs_error) / nullif(sum(y_true), 0)) as accuracy_24h,
       count(*) as n
from v_prediction_scores
where target_at >= now() - interval '24 hours'
group by station_id, model_id;

create view v_active_model as
select * from models where status = 'active';
07

Siete decisiones que no son obvias

  1. station_id es text, no integer

    Los IDs traen ceros iniciales: 03000. Como entero se vuelve 3000 y el join devuelve vacío sin lanzar error. Es el fallo más silencioso de todo el dataset.

  2. La clave primaria natural da idempotencia gratis

    observations tiene PK (station_id, observed_at), así que un on conflict do update hace la ingesta reejecutable. GitHub Actions reintenta; una corrida repetida no puede duplicar filas.

  3. El cursor se deriva, no se guarda aparte

    El reto pide «persistir el cursor o último timestamp». Una tabla de estado mutable puede mentir si una corrida falla a medias. max(observed_at) sobre observations no puede: refleja exactamente lo que aterrizó. El cutoff_at se copia a pipeline_runs solo como registro de auditoría.

  4. Los baselines viven en models

    Registrar el perfil por slot como un modelo más —con su accuracy 88,11 en model_metrics— hace que «comparar contra baselines» sea una consulta y no un apéndice del README. También permite hacerle rollback si el modelo entrenado se degrada.

  5. Las métricas en formato largo

    Una fila por (modelo, split, fold, estación, métrica) en vez de una columna por métrica. Añadir RMSE o una nueva estación no requiere migrar el esquema.

  6. El umbral se guarda junto al valor

    drift_signals.threshold parece redundante. No lo es: los umbrales se ajustan durante la competencia, y sin guardar el vigente no se puede explicar por qué una corrida de octubre no disparó con un valor que en noviembre sí dispara.

  7. La invariante vive en la base

    create unique index ... where status = 'active' hace imposible tener dos modelos activos, incluso con un bug en el código de promoción. Las reglas que importan se ponen donde no se pueden saltar.

Dos cosas que se olvidan y cuestan caro

Concurrencia: añade concurrency: {group: pipeline, cancel-in-progress: false} al workflow. Sin eso, un reintento solapado con la corrida programada produce dos entrenamientos simultáneos compitiendo por el estado active.
Zona horaria: el cron de GitHub Actions corre en UTC. Bogotá es UTC−5. Un cron: "0 6 * * *" se ejecuta a la 1 de la madrugada hora local, no a las 6.

Umbrales derivados del EDA del corte estático de 45 días: banda de ruido semanal de −0,3 % a +5,5 % por estación, accuracy de referencia 88,11 del baseline de perfil (estación × slot × tipo de día) sobre validación temporal de los últimos 7 días. El contrato de submissions aún no se publica: predictions ya deja espacio para él en submit_response.
