## 2. Modelo de datos y ERD

Archivos: [`hallazgos/modelo_datos.html`](../../hallazgos/modelo_datos.html), [`hallazgos/erd.html`](../../hallazgos/erd.html).

Diseño de 10 tablas para soportar el pipeline completo (ingesta, monitoreo, reentrenamiento y predicciones):

| Tabla | Propósito |
|---|---|
| `stations` | Catálogo de las 12 estaciones (semilla, no crece) |
| `pipeline_runs` | Una fila por ejecución del pipeline (estado, commit, métricas) |
| `observations` | Demanda real observada por estación/periodo |
| `context` | Clima y eventos por periodo |
| `run_events` | Log por etapa de cada ejecución |
| `drift_signals` | Señales de drift medidas por corrida (global o por estación) |
| `retrain_decisions` | Decisión de conservar/reentrenar por corrida (1:1 con `pipeline_runs`) |
| `models` | Modelos entrenados, linaje y estado (baseline/activo/retirado) |
| `model_metrics` | Métricas de modelos en formato largo, por split/fold/estación |
| `predictions` | Predicciones emitidas (4 horizontes por corrida) |

15 relaciones (FK) documentadas en el ERD, con notación pata de gallo. Caso particular: `predictions` y `observations` **no** tienen FK entre sí — se comparan por `(station_id, target_at = observed_at)` una vez la observación existe; el scoring se resuelve con una vista (`v_prediction_scores`), no con una columna.
